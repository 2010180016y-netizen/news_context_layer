# 02. 정보 구조(IA) 및 사용자 흐름

## 1. 정보 구조
제품의 정보 구조는 3개 레이어로 나뉜다.

### Layer A. 현재 기사 컨텍스트
사용자가 지금 보고 있는 기사와 직접 연결된 정보
- 현재 기사 출처 카드
- 최신성/업데이트 신호
- 공통 신호 스트립
- 같은 이슈 기사 리스트
- 피드백

### Layer B. 사용자 저장 영역
사용자가 나중에 다시 보기 위해 저장한 정보
- watchlist 목록
- 저장한 cluster
- 최근 본 컨텍스트
- 브리핑 구독 상태

### Layer C. 계정/과금/정책 영역
제품 운영 및 유료화에 필요한 정보
- 플랜 상태
- 결제 내역
- 개인정보/동의
- 이용약관/면책 고지

---

## 2. 내비게이션 구조
Chrome 확장프로그램은 Side Panel 내에서 탭 전환 구조를 단순하게 유지한다.

### Side Panel 주요 탭
1. `현재 기사`
2. `저장한 이슈`
3. `플랜`
4. `설정`

### 탭별 목적
#### 현재 기사
핵심 가치 전달 화면. 첫 진입 화면.

#### 저장한 이슈
무료/유료 전환 트리거가 되는 화면.

#### 플랜
가치 차등 설명과 결제 유도 화면.

#### 설정
동의/알림/도움말/법무 문서 진입 화면.

## 3. 사용자 흐름 맵

### Flow 1. 첫 설치 → 첫 사용
1. 사용자가 Chrome Web Store에서 설치
2. 확장프로그램 아이콘 클릭
3. 온보딩 패널 노출
4. 익명 사용통계 opt-in 선택
5. “현재 기사 비교하기” 클릭
6. Side Panel 열림
7. 현재 기사 컨텍스트 표시
8. 유용성 체감

#### 핵심 성공 포인트
- 설치 후 30초 내 핵심 가치 노출
- 데이터 수집/권한에 대한 불안 최소화

---

### Flow 2. 기사 비교 사용
1. 사용자가 네이버 뉴스 기사 페이지 열람
2. 확장프로그램 액션 버튼 클릭
3. 기사 파싱 시작
4. 로딩 스켈레톤 표시
5. 백엔드에 resolve 요청
6. 컨텍스트 응답 수신
7. 출처 카드, 최신성, 공통 신호, 관련 기사 리스트 표시
8. 사용자가 관련 기사 하나 클릭

#### 실패 흐름
- 파싱 실패 → “지원하지 않는 기사이거나 정보를 충분히 읽지 못했습니다.”
- low confidence → “관련 기사의 정확도가 낮을 수 있습니다.”
- 결과 부족 → “관련 기사를 충분히 찾지 못했습니다.”

---

### Flow 3. 이슈 저장
1. 사용자가 현재 기사 컨텍스트 확인
2. `이 이슈 저장` 클릭
3. 로그인되지 않은 경우 간단한 이메일 수집 또는 로컬 저장 선택
4. Free 사용자는 1개까지 저장 가능
5. 저장 성공 토스트 노출
6. watchlist 탭에서 저장 목록 확인

#### Free 제한 도달 흐름
1. 이미 1개 저장된 상태에서 새 이슈 저장 시도
2. paywall 또는 Founder Pass 패널 노출
3. Pro/Founder Pass 혜택 설명

---

### Flow 4. 피드백 제출
1. 사용자가 `도움 됐어요` 또는 `관련도 낮아요` 클릭
2. 선택형 옵션 노출
3. 선택 후 전송
4. 짧은 감사 메시지 표시

#### 목적
- 관련도 개선 학습 데이터 확보
- 제품 적합성 검증

---

### Flow 5. 결제
1. 사용자가 paywall 진입
2. Free와 유료 기능 비교 확인
3. Founder Pass 또는 Pro 버튼 클릭
4. 결제 페이지 이동
5. 결제 완료 후 플랜 반영
6. watchlist 한도/브리핑 기능 활성화

---

### Flow 6. 저장한 이슈 재방문
1. 사용자가 Side Panel → 저장한 이슈 탭 진입
2. 저장 목록 확인
3. 특정 이슈 클릭
4. cluster 상세 또는 최신 기사 목록 확인
5. 관련 기사 재클릭 가능

---

## 4. 상태 정의
### 기사 컨텍스트 상태
- `idle` : 아직 실행 안 함
- `loading` : 기사 파싱 또는 컨텍스트 로딩 중
- `success` : 정상 결과 표시
- `partial_success` : 결과는 있으나 low-confidence 또는 기사 수 부족
- `unsupported` : 지원 안 되는 기사
- `error` : 시스템 오류

### 사용자 상태
- `anonymous_local` : 로그인 없이 로컬 저장만 사용
- `guest_tracked` : 익명 ID 있음
- `registered_free`
- `paid_founder`
- `paid_pro`
- `paid_analyst`

### 결제 상태
- `inactive`
- `active`
- `expired`
- `grace_period`
- `refunded`

## 5. 기능별 트리거 포인트
### 패널 열기 트리거
- 사용자 액션 버튼 클릭
- 최초 설치 후 CTA 버튼 클릭

### paywall 트리거
- watchlist 2개째 저장 시도
- 저장 이슈 브리핑 보기 시도
- 저장 히스토리 7일 초과 보기 시도

### 피드백 트리거
- 관련 기사 클릭 후 5초 이상 체류
- 패널 닫기 직전 간단 CTA
- low-confidence 결과 표시 후 “결과가 아쉬웠나요?”

---

## 6. 콘텐츠 우선순위
### 현재 기사 패널 우선순위
1. 출처 카드
2. 최신성 신호
3. 공통 신호 스트립
4. 같은 이슈 기사 리스트
5. 저장 CTA
6. 피드백
7. 면책 고지

### 이유
- 사용자는 먼저 “무슨 기사인지”를 확인해야 한다.
- 다음으로 “더 최신 정보가 있는지”가 중요하다.
- 그다음 “비교 결과가 요약되어 있나”를 본다.
- 마지막으로 저장/결제를 고려한다.

## 7. 정보 구조 원칙
### 원칙 1. 판정 대신 신호
UI 문구는 절대 단정하지 않는다.
- 사용: “관련 기사를 찾았습니다”, “더 최신 보도가 있습니다”
- 금지: “사실 아님”, “틀린 기사”, “가짜 뉴스”

### 원칙 2. 한 화면, 한 핵심 가치
현재 기사 화면은 `비교`가 핵심이다. 설정/플랜/정책은 보조다.

### 원칙 3. 사용자는 기사 읽는 흐름을 끊기 싫어한다
메인 경험은 1~2회 클릭 안에 끝나야 한다.

### 원칙 4. 저장과 알림은 2차 가치
사용자가 첫 가치(비교)를 경험한 뒤에만 노출 강도를 높인다.

## 8. 유료 전환 경로
### 전환 경로 A. 저장 한도 기반
- 비교 사용 → 저장 1회 → 2번째 저장 시 paywall

### 전환 경로 B. 브리핑 기반
- 저장한 이슈 생성 → 브리핑 미리보기 → 전체 열람 paywall

### 전환 경로 C. 히스토리 기반
- 저장하지 않았지만 최근 본 이슈 재진입 시도 → 히스토리 확장 paywall

---

## 9. 운영 관점 사용자 세그먼트
### Segment A. 탐색형 사용자
- 패널만 열어 보고 저장 안 함
- 주 KPI: D1 activation

### Segment B. 반복형 사용자
- 2회 이상 패널 사용
- 주 KPI: D7 repeat

### Segment C. 저장형 사용자
- watchlist 생성
- 주 KPI: save rate

### Segment D. 유료형 사용자
- paywall view 후 결제
- 주 KPI: conversion

### Segment E. B2B 후보
- 특정 키워드 이슈를 반복 저장
- 같은 산업/기업 키워드를 자주 보는 사용자
- 주 KPI: inquiry / demo request
